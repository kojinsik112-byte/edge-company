# 착수는 새 세션에서 (본부장 10-23 '착수팀은 새로운 세션으로')

빌드 · 제출 · 업로드 세션과 착수(새 공고 분석) 세션을 나눈다. 대화가 길어져도 착수 결과는 깃으로 넘어온다.

## 1. 새 세션 여는 법
1. claude.ai/code → 새 세션 → 저장소 `kojinsik112-byte/edge-company`
2. **브랜치를 `claude/edge-company-proposal-revision-6al3m1`로 고른다.** 기본 브랜치(`claude/sharp-feynman-MfQx9`)에는 착수 스킬 · 입찰본부 팀 · 도구가 없다.
3. 공고 파일(hwp · hwpx · pdf · docx · 별지 양식)을 첨부하고 아래 문장을 붙여 넣는다.

```
/kickoff <단지명>
작업 브랜치 = claude/edge-company-proposal-revision-6al3m1 (본부장 허락 · 이 브랜치에 바로 푸시).
시작 전 git pull, 끝나면 git push. 손대는 곳은 jugansa/착수/<약칭>* 와 jugansa/CLAUDE.md '진행 중 입찰' 한 줄 · jugansa/입찰현황판.md 한 줄뿐.
업로드하지 않는다. 결과는 jugansa/착수/<약칭>.md 로 남기고 끝에 '빌드 세션에 넘길 말' 한 줄.
```

## 2. 착수 세션이 남기는 것 (깃)
| 파일 | 내용 | 개인정보 |
|---|---|---|
| `jugansa/착수/<약칭>.md` | 결론 3줄 · 사업성 · 지원금 상한 · 일정 · 제출서류 체크리스트 · 함정 · 질의 메일 초안 · 복제 출발점 · 본부장 결정 · 남은 일 | 입예협 임원 이름 · 연락처 · 카페 닉네임 쓰지 않음 |
| `jugansa/착수/<약칭>_공고원문_가림.txt` | `jugansa/tools/mask_notice.py`로 전화 · 메일 · 주민번호 · 계좌를 가린 공고 원문(접수 메일은 `--keep`) | 남은 이름은 눈으로 확인 |
| `jugansa/CLAUDE.md` '진행 중 입찰' | 단지 한 줄(세대 · 마감 · 메일 · 제목 · 결론) | |

착수 보고서 PDF(`jugansa/tools/kickoff_report.py`)는 내부용 — 그 세션에서 본부장께 바로 보내고 깃에는 올리지 않는다.

## 3. 빌드 세션으로 넘기기
빌드 세션에서 "**<약칭> 착수 결과 받아서 시작하자**" → 빌드 세션이 `git pull` 후 `jugansa/착수/<약칭>.md` · 가린 원문을 읽고 복제 출발점 빌더부터 만든다.

## 4. 착수 세션에서 못 하는 것
- 증빙 원본 · 직인 · 날인 스캔은 빌드 세션 임시 폴더에만 있다 → 착수는 `jugansa/착수/증빙_발급일.md`로 보유 여부만 판단한다.
- 클라우드 세션은 네이버 카페 · 스마트스토어 직접 접속이 막힌다 → 카페 회원 수 · 공지는 본부장께 묻는다(착수 질문 1번).
